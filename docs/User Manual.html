Using scrap

How to install scrap, download files (even very large ones), copy an entire website, use the filters to choose what to download, get into sites with restricted access and cope when something goes wrong. At the end you will find the complete reference of every option.

Version 1.1 System Linux (x86-64 and 64-bit ARM) Program a single file, nothing to install

Contents

Press / to search. The index at the end lists options, files and topics.

Introduction

What scrap is, what it does and what it deliberately does not do.

What it is

scrap is a terminal program for downloading from the web. It combines in a single tool two things that usually take two different programs: downloading a file quickly, by opening several connections at once to the same file, and copying an entire website (or part of it) by following the links from one page to the next. On top of that there are many filters for choosing exactly what to keep: only the images, only the PDFs under a certain size, only the pages of a certain site, and so on. That is why we call it «the Swiss Army knife of downloading».

It is a single executable file: it needs nothing else installed, not even the security certificates for https sites, which it carries with it.

⇉

Multiple connections per file

Splits a large file into 4 pieces (or as many as you like) downloaded at the same time: often much faster.

↺

If the connection drops it retries on its own; if you stop it, run it again with -c and it picks up where it left off.

Follows the links in the pages and rebuilds the site's folders on your disk, even for browsing offline.

⚙

By file type, size, name, site, total amount: you download only what you are interested in.

🔒

Restricted access

Username and password, login through a web form, tokens, browser cookies.

Built-in help

scrap --help opens a tabbed help screen in the terminal.

What it does not do

  • It does not run JavaScript. scrap reads pages exactly as they arrive from the server: sites that build their content in the browser with JavaScript (many modern sites) can only be partly copied.
  • It does not get around protections: captchas, waiting times, limits. For file hosting sites with accounts there is the sister project hoster.
  • By default it respects robots.txt, the file with which a site asks automated programs not to visit certain parts (see The site's rules).
Intended use

Downloading content you are authorized to download, at a pace that is respectful of the servers. When you copy a site that is not yours, keep the number of simultaneous downloads low (-j) and, if the site is small, limit the bandwidth (--rate).

How it works, in brief

flowchart LR
  A["one or more addresses<br/>(or a list with -i)"] --> B{"-r or -m?"}
  B -->|"no"| C["downloads each file<br/>over multiple connections"]
  B -->|"yes"| D["reads the pages<br/>and follows the links"]
  D --> E["filters: what to keep"]
  E --> C
  C --> F["files on disk<br/>(resume with -c)"]

Without any particular options scrap downloads the addresses you give it. With -r (or -m) it opens the web pages, collects their links and carries on from page to page, keeping only what passes the filters.

Installation

Three ways: the ready-made program in the repository, the ready-made program from the releases, or building it from the source code.

The ready-made program, with git clone

The repository already contains the compiled program, the file scrap (for Linux PCs and tablets with an Intel or AMD processor). Just clone it:

$ git clone https://github.com/nic-fio/SCRAPER.git
$ cd SCRAPER
$ ./scrap --help

Nothing else needs to be installed.

Just the program, from the releases

On the releases page on GitHub there are two files:

FileFor
scrap-linux-amd64Linux PCs and tablets with an Intel or AMD processor (most of them).
scrap-linux-arm64Raspberry Pi 4 or 5 and other 64-bit ARM devices.

If you do not know which one you need, the command uname -m tells you: x86_64 means amd64, aarch64 means arm64. For other systems (Mac, Windows, 32-bit ARM) the program can be built from the source: see the technical manual. Once the file is downloaded:

$ mv ~/Scaricati/scrap-linux-amd64 scrap
$ chmod +x scrap
$ ./scrap --help

The release page also contains SHA256SUMS, to check that the file arrived intact: sha256sum -c SHA256SUMS --ignore-missing.

Using it from any folder

To type just scrap instead of ./scrap, copy it into a program folder (it asks for the password):

$ sudo install -m 0755 scrap /usr/local/bin/scrap
$ scrap --help

In the examples in this manual the program is simply called scrap.

From the source code

You need a Debian or Ubuntu machine with an Internet connection. The script tools/setup-dev.sh checks and installs whatever is missing (the Go compiler and a few other packages; it asks for the password for sudo):

$ git clone https://github.com/nic-fio/SCRAPER.git
$ cd SCRAPER
$ tools/setup-dev.sh --install
$ make
$ make test

make rebuilds the scrap program from the code; make test runs all the automatic checks. You only need this if you want to modify scrap.

First steps

The first download, what you see on the screen and where the files end up.

Downloading a file

$ scrap https://esempio.it/immagini/debian.iso

The file is saved in the folder you run the command from, with its own name (debian.iso). While it downloads, scrap shows one line for each file in progress:

 ⬇ debian.iso          ▕██████████▎░░░░░░▏  64%  503M/781M  17.0M/s  16s
    └ seg ▰▰▱▱ ▰▰▰▱ ▰▰▰▰ ▰▰▱▱  (4 connessioni)
────────────────────────────────────────────────────────────────────────
 1 attivi · 0 fatti · 503M · 17.0M/s

On the first line: name, bar, percentage, how much has arrived out of the total, speed and time remaining. The line └ seg shows the pieces of the file arriving in parallel, one per connection («connessioni» means connections). At the bottom, the count of files active and finished («attivi», «fatti»), the total downloaded and the overall speed. When a file finishes, a line with ✓ appears in its place; at the end, the summary («media» means average):

 ✓ debian.iso  781M  16.4M/s
✓ 1 file · 781M in 48s · media 16.4M/s

If something went wrong, the summary starts with ✗ and says how many addresses failed; the reason is written above it, on a line that starts with scrap:.

Where it saves and under what name

  • Folder: with -d you choose where to save (the folder is created if it does not exist): scrap -d ~/iso https://…/debian.iso.
  • Name: with -o you choose the file name: scrap -o debian-12.iso https://…/download?id=42. It applies to a single address: with several addresses, or together with -r/-m, scrap stops and asks you to use -d.
  • Odd names: accented letters, spaces and symbols in the name are replaced with _; if the address has a part after the ?, it ends up in the name after an @ (download@id_42). With -o you choose a clean name yourself.

While a file is in progress it is called NOME.part; it takes its final name only when it is complete.

Downloading a list of addresses

Put the addresses in a text file, one per line. Empty lines and lines that start with # are skipped:

# ISOs to download tonight
https://esempio.it/debian.iso
https://esempio.it/ubuntu.iso

$ scrap -i lista.txt -d ~/iso

You can also write several addresses directly in the command, one after the other, and combine them with -i.

Downloading files

How scrap behaves while downloading and how to adjust it.

Connections per file

By default scrap splits each file into 4 pieces downloaded at the same time, each with its own connection. Many servers limit the speed of each single connection: with more pieces at once you get there faster. -s 8 uses 8 connections, -s 1 just one.

The split happens only if the server accepts downloads «in pieces» and if the file is at least 1 MB (--min-split changes the threshold). Otherwise scrap downloads the file over a single connection, without you having to do anything.

How many files at once

By default scrap works on 4 files at a time (-j changes the number). With a long list, -j 8 goes faster if the line can take it; -j 1 downloads one file at a time. When you copy a site, the same number applies to the pages read at the same time.

Interruptions and resuming

If the connection drops, scrap retries on its own up to 5 times (--retries) and restarts from the point it had reached. Between one attempt and the next it waits 2 seconds, then 4, then 8… up to a maximum of one minute (--retry-wait sets the initial wait); if the server says how long to wait, scrap waits that long. It does not retry, however, when the server answers with a permanent refusal, for example «file not found» (404) or «access denied» (403): trying again would change nothing.

If you stop the program yourself (Ctrl+C), run the same command again adding -c:

$ scrap -c -i lista.txt -d ~/iso

Files left half-finished (.part) restart from where they had got to. Files that are already complete are always skipped, with or without -c: the summary counts them as già presenti (already present).

Good to know

Without -c a half-finished file starts again from zero. After a sudden power-off (flat battery, not Ctrl+C) it is safer to delete the .part of that file and download it again: the last data written before the power-off may not have reached the disk.

Limiting the bandwidth

--rate sets an overall limit, valid for all downloads together:

$ scrap --rate 2M -i lista.txt

Sizes in scrap are written as a number and a unit: k (kilobytes), M (megabytes), G (gigabytes), T, also in lower case and with decimals (1.5M); the form 10MB works too. For --rate they are bytes per second: 2M is about 2 megabytes per second, that is about 16 megabits. 0, the default value, means no limit.

Slow or unstable networks

--timeout (60 seconds) is the maximum waiting time when the server does not respond: to connect, for the first response and, during a download, without receiving even a single byte. It does not limit the duration of a download: a file of many gigabytes can take hours. If the server stalls halfway, after --timeout seconds scrap interrupts and retries from the right point. On a very slow network you can raise it, for example --timeout 120 --retries 10.

Copying a website

Following the links from one page to the next and rebuilding the site on disk.

Following the links

$ scrap -r https://esempio.it/manuali/

With -r scrap opens the page, collects all its links (hyperlinks, images, style sheets, scripts, videos…) and downloads them; for every web page it finds it repeats the same work. It stops after 5 steps of links from the starting page: the depth, which you change with -l (-l 2: the starting page, the pages it leads to, and the ones those lead to). -l inf removes the limit.

Full copy

$ scrap -m --convert-links https://esempio.it/

-m is the full copy of a site: like -r, but with no depth limit. With --convert-links, at the end scrap rewrites the links in the saved pages so that they point to the files on your disk: open esempio.it/index.html in the browser and you can browse even without a network.

How the files are saved

With -r and -m scrap rebuilds the site's folders, inside a folder named after the site:

esempio.it/
├── index.html              ← the page https://esempio.it/
├── chi-siamo.html
├── manuali/
│   ├── index.html          ← the page https://esempio.it/manuali/
│   └── guida.pdf
└── img/
    └── logo.png

An address ending in / becomes index.html; a web page without an extension gets .html added at the end. Without -r/-m, on the other hand, each file goes straight into the destination folder, with just its name.

Staying within the site

  • Other sites: by default scrap follows only links to the starting site (and its subdomains: starting from esempio.it, www.esempio.it is fine too). --span-hosts removes this limit: always use it together with a filter, otherwise you risk downloading half the web.
  • Chosen sites: --domains esempio.it,cdn.esempio.net follows only these sites; --exclude-domains pubblicita.com excludes them.
  • Only below a folder: --no-parent does not go above the starting folder. Starting from https://esempio.it/manuali/ it downloads /manuali/… but not /blog/.

Pages complete with images and styles

A web page on its own is not enough to display it properly: it needs its images, style sheets and scripts. With -r they are already downloaded, except at the maximum depth, where scrap stops. With --page-requisites the resources of the pages are always downloaded, even at the last level and even outside --no-parent. Without -r, it saves a single complete page:

$ scrap --page-requisites --convert-links https://esempio.it/articolo.html

The site's rules

Many sites have a robots.txt file that asks automated programs not to visit certain parts. When it copies a site, scrap reads it and respects it: forbidden addresses are skipped (with -v you see it written: bloccato da robots.txt, blocked by robots.txt). --robots=false ignores these rules: use it only on your own sites or when you have permission. For single files downloaded without -r, robots.txt is not consulted.

Filters

Choosing exactly what to download: the heart of the knife.

By file type

$ scrap -r -A jpg,png,pdf https://esempio.it/

-A keeps only the files with those extensions; -R discards the ones listed (for example -R zip,exe). Upper and lower case are the same, the leading dot is optional.

While a site is being copied, web pages are still read to find their links, but they are saved only if they pass the filters. With -A jpg,png, therefore, scrap goes through all the pages but on disk you find only the images. To keep the pages too, add html to the list (pages without an extension, such as /manuali/, count as html).

By name or address

--accept-re follows only the addresses that contain a certain pattern, --reject-re excludes the ones that contain it. The pattern is a regular expression, a compact way of describing text:

WriteIt means
--reject-re '/tag/|/autore/'skip the addresses that contain /tag/ or /autore/
--accept-re '2024'only the addresses that contain 2024
--reject-re '\?'skip the addresses with a ? (often the site's sorting and filter options)

Write the pattern between single quotes, as in the examples, so that the terminal does not change its symbols.

Caution

These two filters apply to every address, including the pages to go through and the starting one: with --accept-re 'pdf$' scrap discards the starting page straight away and downloads nothing. To keep only certain files without blocking navigation use -A pdf; --accept-re is for narrowing the tour, for example --accept-re '/manuali/'.

By size

--min-size 100k skips files smaller than 100 kilobytes (useful for discarding thumbnails and icons), --max-size 50M those larger than 50 megabytes. The size is checked before downloading; if the server does not declare it, the file is downloaded.

By content

The server declares what it is sending (the content type): image/jpeg, application/pdf, text/html… --types keeps only the listed types; with /* at the end you take a whole family:

$ scrap -r --types 'image/*,application/pdf' https://esempio.it/

It is more reliable than -A when the addresses have no extension (for example /scarica?id=42).

How much in total

  • --max-files 200: stops after saving 200 files (saved web pages count).
  • --quota 2G: stops after downloading 2 gigabytes in total. Downloads already under way may go slightly over the limit; a file interrupted by the quota stays .part.

Examples

ForCommand
All the PDFs of a sitescrap -m -A pdf https://esempio.it/
The photos, no thumbnails, at most 500scrap -r -A jpg,jpeg,png --min-size 50k --max-files 500 https://esempio.it/galleria/

Sites with restricted access

Downloading from sites that ask for a username and password, a login or a token.

Server username and password

Some sites ask for a username and password in a small browser window, before even showing the page. For these:

$ scrap --user mario --password 'segreta' https://esempio.it/riservato/file.zip

scrap recognizes on its own the two systems in use (Basic and Digest). --auth digest avoids sending the password in readable form until the server asks for it the Digest way.

Login through a web form

Many sites have a login page with a form. scrap can submit it before starting and then use the session it obtains:

$ scrap --login-url https://esempio.it/login --login-data 'utente=mario&password=segreta' \
        --save-cookies sessione.txt -m https://esempio.it/area-soci/

--login-data takes the names of the form fields, which you find in the code of the login page (in the browser: right-click on the field, «Inspect», attribute name). With --save-cookies the session is saved to a file; next time you just load it, without logging in again:

$ scrap --load-cookies sessione.txt https://esempio.it/area-soci/altro.pdf

The format is the standard cookies.txt one: you can also export the cookies from the browser with an extension and load them with --load-cookies. It is the safest way for sites with a complicated login (captchas, codes by SMS): you log in in the browser, export the cookies, download with scrap.

Limitation

Form login sends only the fields you write. If the login page contains a hidden code that changes at every visit (many sites do this for security), the login fails: use the cookies exported from the browser.

Tokens, headers and hand-written cookies

  • --bearer TOKEN: for services that give you an access token (typical of APIs).
  • -H 'Nome: valore': adds any header to the request; it can be repeated.
  • --cookie 'nome=valore; altro=valore': sends hand-written cookies.
  • --referer and -U: tell the server which page you are coming from and which program you present yourself as (see the reference).
Be careful with passwords

Passwords and tokens written in the command stay in the terminal history and, while scrap is working, are visible to the other users of the same computer. Cookie files (sessione.txt) are as good as a password: whoever has them gets into the site in your place. Do not share them and do not upload them to GitHub (the scrap repository ignores the names cookies.txt, cj.txt and *.cookies).

Messages and silence

Seeing more, or less, of what is going on.

OptionWhat you see
(none)Bars, a ✓ line for each finished file, the errors, the summary.
-vIn addition, the reason for every choice: files skipped by the filters or by robots.txt, files already present, new attempts with the reason.
-qeOnly the errors.
-qaNothing at all. How it went is told only by the exit status.

When the output does not go to a screen (for example scrap … 2> registro.txt), scrap writes plain text lines instead of the bars. The variable NO_COLOR turns off the colors: NO_COLOR=1 scrap ….

Other situations

The site copy downloads almost nothing
Run it again with -v and look at the reason. The most common causes: robots.txt forbids the site; the site builds its pages with JavaScript; the links lead to another address (for example from esempio.it to esempio.com: add it with --domains); an --accept-re filter also blocks the pages.
The summary says «0 file» but the files are there
The files were already complete from a previous run and were skipped: the summary counts them as già presenti (already present).
Downloads are slow
Check that you have not given --rate. Try more connections per file (-s 8) and more files at once (-j).
I don't see the bars, only lines of text
It happens when the output does not go to a terminal (for example if you send it to a file): it is intentional. At most 6 bars are visible at once; the other files in progress are summarized in …e altri N in corso (…and N more in progress).
I use it in a script
Check the exit status: 0 if everything went well, 1 if at least one address failed, 2 for a wrong option. -qa removes all messages.

Option reference

All the options, with the value used if you do not specify them. They can be written with one or two dashes: -mirror and --mirror are the same thing. Options must be written before the addresses.

Download

-s, --split N
Connections (pieces) for each file. Default: 4. See Connections per file.
-j, --jobs N
Files (and pages) worked on at the same time. Default: 4.
--min-split SIZE
Below this size a file is downloaded over a single connection. Default: 1M.
-o, --output FILE
Name (and path) of the file to save. Only with one address and without -r/-m.
-d, --dir DIR
Folder to save into (created if it does not exist). Default: the current folder.
-c, --continue
Resumes files left half-finished (.part). Complete files are always skipped. See Interruptions and resuming.
--retries N
New attempts after the first, for each file or piece. Default: 5. Permanent refusals (401, 403, 404…) are not retried.
--retry-wait SEC
Wait before the first new attempt; then it doubles at every attempt, up to 60 seconds. Default: 2.
--rate SIZE
Overall bandwidth limit, per second, for example 2M. Default: 0, no limit.
--timeout SEC
Maximum wait when the server does not respond or stops sending data. It does not limit the duration of a download. Default: 60; 0 removes the limit.

Copying sites

-r, --recursive
Follows the links in the pages and rebuilds the site's folders.
-l, --level N
Maximum depth: how many steps of links from the starting page. inf = no limit. Default: 5.
-m, --mirror
Full copy: like -r -l inf.
--no-parent
Does not go above the folder of the starting address (the first one, if there are several).
--span-hosts
Also follows links to other sites. To be used with a filter.
--page-requisites
Always downloads the resources of the pages (images, styles, scripts), even at the last level. Without -r: a single complete page. See Complete pages.
--convert-links
At the end rewrites the links in the saved pages to point to the files on disk, for browsing without a network.
--robots=false
Ignores robots.txt. Default: the site's rules are respected.

Filters

-A, --accept LISTA
Extensions to keep, separated by commas: jpg,png,pdf.
-R, --reject LISTA
Extensions to discard.
--accept-re REGEX
Only the addresses that match the regular expression (pages included).
--reject-re REGEX
Discards the addresses that match the regular expression.
--domains LISTA
Only these sites (and their subdomains). Replaces the default limit to the starting site.
--exclude-domains LISTA
Never these sites.
--min-size SIZE
Skips smaller files.
--max-size SIZE
Skips larger files.
--types LISTA
Content types to keep, for example image/*,application/pdf.
--max-files N
Stops after saving N files. Default: 0, no limit.
--quota SIZE
Stops after downloading SIZE in total. Default: 0, no limit.

Access and cookies

--user UTENTE
Username for the server's access control (Basic or Digest).
--password PASS
Password for the server's access control.
--auth MODO
auto (default) or basic: sends the username and password straight away, and switches to Digest if the server asks for it. digest: sends them only when the server asks for them the Digest way.
--login-url URL
Address to which the login form is submitted before starting.
--login-data DATI
Fields of the login form: utente=mario&password=segreta.
--bearer TOKEN
Access token, sent as Authorization: Bearer TOKEN.
-H, --header 'Nome: valore'
Additional header for every request; it can be repeated.
--cookie 'k=v; …'
Hand-written cookies, sent with every request.
--load-cookies FILE
Loads the cookies from a cookies.txt file (Netscape format, the one browsers use).
--save-cookies FILE
At the end saves the cookies to a cookies.txt file.

General

-U, --user-agent UA
How scrap presents itself to sites. Default: scrap/1.1 (+https://github.com/nic-fio/SCRAPER), an honest and recognizable name. Change it only if a site rejects programs.
--referer URL
The page you say you are coming from; some sites check it before handing over a file.
--insecure
Does not check the security certificates of https sites. It removes a protection: use it only if you know why.
-qe
Shows only the errors.
-qa
Shows nothing, errors included. The exit status remains the real one. Only an option unknown to the program is reported anyway.
-v, --verbose
Explains every choice: files skipped and why, new attempts, login.
-i, --input-file FILE
Reads the addresses from a file, one per line. See Downloading a list.

Exit statuses

StatusWhen
0Everything downloaded. Files already present, which are skipped, count as successful; so do files excluded by the filters or by robots.txt.

Glossary

Crawl, site copy
Visiting a site by following the links from one page to the next, as a person would, but automatically.
Depth
How many links you have to follow from the starting page to reach a page.
Piece (segment)
A part of a file downloaded over its own connection, together with the others.
Extension
The final part of a file name after the dot: jpg, pdf, zip.
Regular expression
A compact way of describing text: a|b means «a or b», $ the end, . any character.
Cookie
A small piece of data that the site leaves in the browser to recognize it on later visits, for example after logging in.
robots.txt
A site's file with the rules for automated programs: which parts not to visit.
Certificate
The digital document with which an https site proves its identity.
Release
A published version of the program, with the files ready to download.
